# files.py — файлы по SFTP `/files/<ip>`

**Точки входа:** `/files/<ip>`, `/api/files/connect`, `/api/files/disconnect`,
`/api/files/session`, `/api/files/list`, `/api/files/download`,
`/api/files/zip`, `/api/files/upload`, `/api/files/op`, `/api/files/to-drop`,
`/api/files/to-drop/<job_id>`.

**Что это:** файловый менеджер (список/папки/скачивание/загрузка/
переименование/удаление/zip папки) поверх SSH — не отдельная служба, тот же
порт 22 через NetBird и тот же логин/пароль, что у консоли. Кто видит
кнопку: машины с `ssh_enabled` + те, у кого в `NETBIRD_DEVICES` стоит
`sftp_enabled` (виндовые с ручным OpenSSH). Быстрый вход без повторного
пароля — `quickSftpConnect` из `remote.py`, см. `remote.md`.

## Два бэкенда за одним интерфейсом

`AgentBackend` в этом файле повторяет ту часть `paramiko.SFTPClient`,
которой пользуется страница (`normalize · listdir_attr · stat · open ·
mkdir · rename · remove · rmdir`), но шлёт команды телефонному агенту в его
сокет (`PhoneFs` в `blueprints/phone.py`) вместо настоящего SFTP.
Маршрутизация — `_is_phone(ip)`. Верстка и API `/files` НЕ переписаны под
это — общий интерфейс сделал подмену прозрачной. Протокол с телефоном
(`{"type":"fs",...}`, кадры `[тип=4][номер запроса:4][байты]`) и права
(`MANAGE_EXTERNAL_STORAGE`) — подробности в `phone.md`. Логин к файлам
телефона отдельный (`PHONE_FILES_USER`/`PHONE_FILES_PASSWORD`), не путать с
`PHONE_AGENT_TOKEN`.

## Кнопка VG → перенос в дроп

Значок монограммы у каждого файла/папки переносит их **напрямую с машины в
дроп** тем же SFTP-соединением, минуя браузер: читает через
`sftp.open()`/`listdir_attr()`, пишет в `drop_path(item_id)`, регистрирует в
`drop_items` с `parent=DROP_DOWNLOAD_ID` (см. `drop.md`). Квота дропа
проверяется дважды — до чтения (по заявленному `stat().st_size`) и после
записи (по факту). **Не откатывается при частичном провале** — уже
перенесённое остаётся, сознательный компромисс (как `_rm_tree`/`_zip_plan`).

Перенос **асинхронный**: `POST /api/files/to-drop` сразу считает общий
размер (`_to_drop_plan_size`) и отвечает `{job, name, total, kind}`, сама
передача — в фоновом потоке; страница опрашивает
`GET /api/files/to-drop/<job_id>`. Виджет `#dl-wrap` в `files.html`.

## Инварианты (нельзя ломать)

- Скачивание отдаётся генератором с `application/octet-stream` — этого
  типа нет в `GZIP_TYPES`, иначе `compress_response` собрал бы поток в
  буфер.
- Имя при загрузке режется через `posixpath.basename` (`../` не уводит
  выше папки).
- Непустую папку с первого раза не удаляем — сервер отвечает
  `needs_recursive`, страница спрашивает отдельно.
- **Один `SFTPClient` не потокобезопасен** — любое обращение к `sftp`
  (включая тело потоковых генераторов `files_download`/`files_zip`)
  обёрнуто в `entry["io_lock"]` (`threading.Lock`, один на соединение):
  фоновый перенос VG живёт своим потоком параллельно обычным запросам той
  же вкладки.
- Пароль SSH на диск не пишется. Простой дольше 15 минут закрывает
  соединение (поток-дворник).
