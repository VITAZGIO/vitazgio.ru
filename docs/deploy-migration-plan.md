# ТЗ: перенос автодеплоя на VPS в Амстердаме

**Статус: выполнено (2026-09-04).** Хроника — в `docs/history.md`,
раздел «CI/CD: перенос автодеплоя с дома на VPS в Амстердаме». Текст
ниже оставлен как справка — что и зачем делали, план сработал без
отката.

Цель: правки, слитые в `main`, собираются и стартуют **прямо на VPS в
Амстердаме**, без прыжка через домашний сервер. Домашний сервер выходит
из автоматики целиком — его больше не трогает НИ ОДИН workflow. Обновлять
его (редко — там живёт только `guacd`) — вручную, одной командой.

Повод: домашняя машина зависла → встал весь конвейер, включая merge в
main, который к дому вообще отношения не имеет (чистый git, никакой
site-специфики). План убирает эту точку отказа насовсем, а не только
удаляет SSH-прыжок.

## Часть 1 — VPS в Амстердаме: поставить туда раннера GitHub Actions

**Машина: VPS в Амстердаме (`root@100.104.94.83`).**

1. В браузере: `github.com/VITAZGIO/vitazgio.ru` → **Settings** →
   **Actions** → **Runners** → **New self-hosted runner** → выбрать
   **Linux x64**.
2. GitHub покажет команды с одноразовым токеном регистрации — выполнить
   их ПРЯМО НА VPS (не дома), по порядку (скачать архив, распаковать,
   `./config.sh`). На вопрос про **labels** во время `config.sh` указать
   свою метку, например `vps-amsterdam` (чтобы workflow мог целиться
   именно в эту машину и не путать её с домашней, если та останется
   зарегистрирована).
3. Поставить как systemd-сервис (а не голым процессом в screen/tmux —
   именно так домашний был живым `active running` даже после нашего
   сегодняшнего разбора, но лучше сразу так и делать):
   ```bash
   sudo ./svc.sh install
   sudo ./svc.sh start
   sudo systemctl enable actions.runner.*   # автозапуск после ребута VPS
   ```
4. Проверить в GitHub Settings → Actions → Runners: новая строка со
   статусом **Idle** и меткой `vps-amsterdam`.

## Часть 2 — Упростить `.github/workflows/deploy.yml`

**Правки — код, применяются через обычный пуш (это могу сделать я).**

Убрать SSH-прыжок целиком (мы уже НА целевой машине), убрать шаг
«Restart guacd at home» (это дом, сюда не относится), нацелить job на
новую метку:

```yaml
jobs:
  deploy:
    runs-on: [self-hosted, vps-amsterdam]

    steps:
      - name: Sync code from GitHub
        run: |
          cd /opt/sites/vitazgio.ru
          git fetch origin
          git reset --hard origin/main

      - name: Clean up Docker cache
        run: |
          docker builder prune -af
          docker image prune -f

      - name: Build and deploy
        run: |
          cd /opt/sites/vitazgio.ru
          docker compose up -d --build web
          docker builder prune -f
          docker image prune -f
```

## Часть 3 — `.github/workflows/claude-automerge.yml`: merge — на GitHub-хостинге, не дома

**Правки — код (я делаю).**

Шаг `merge` — чистый git (клонировать, `py_compile`, смержить, запушить),
никакой зависимости ни от дома, ни от Амстердама. Сейчас он висит на
`runs-on: self-hosted` — то есть на домашней машине, и когда та зависла,
встал даже мердж, хотя ему дом не нужен вообще. Переносим на
GitHub-хостед раннер:

```yaml
jobs:
  merge:
    runs-on: ubuntu-latest
    ...
  deploy:
    needs: merge
    uses: ./.github/workflows/deploy.yml
```

`ubuntu-latest` — виртуалка самого GitHub, бесплатная в пределах обычных
лимитов, никогда не «зависает у тебя дома» — она просто не твоя.

## Часть 4 — Домашний сервер: выходит из автоматики

После частей 2-3 ни один workflow домашнюю машину не трогает. Варианты
по раннеру на ней (на твой выбор, не критично):
- **оставить как есть** (`active running`) — просто больше не получает
  задач, лежит про запас;
- **остановить**, раз не нужен: `sudo systemctl disable --now
  actions.runner.VITAZGIO-vitazgio.ru.ubuntu-server.service` — и в
  GitHub Settings → Runners его можно удалить (Remove).

Обновление `guacd` дома — вручную, командой из начала этого документа
(`git pull && docker compose up -d guacd`), когда реально что-то поменял
в его конфиге (по твоим словам — редко).

## Порядок внедрения (без даунтайма)

1. Часть 1 — регистрируешь раннера на VPS (только твои руки, я тут не
   помогу — нужен твой GitHub-логин и живой токен с UI).
2. Как только в Settings → Runners новая строка `vps-amsterdam` станет
   **Idle** — говоришь мне, я пушу правки из частей 2 и 3.
3. Проверяем одним тестовым пушем в `claude/**` — должно: смержиться на
   `ubuntu-latest` (видно в логах рана), задеплоиться прямо на
   `vps-amsterdam` (без единого упоминания SSH/100.104.94.83 в логе).
4. Если всё зелёное — часть 4 (домашний раннер) по желанию, не срочно.

## Откат

Если что-то пойдёт не так на шаге 3 — просто верни `deploy.yml` и
`claude-automerge.yml` предыдущими коммитами (`git revert`), домашний
раннер всё ещё зарегистрирован и рабочий, старая схема тут же поедет
как прежде.
