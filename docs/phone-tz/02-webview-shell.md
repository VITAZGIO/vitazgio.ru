# ТЗ 2. Оболочка-браузер: сайт живёт внутри приложения

**Делать, пока идёт ночной тест из ТЗ 1** — от него это задание не зависит,
и сутки ожидания не должны простаивать.

## Зачем

Хозяин и так ходит на vitazgio.ru с телефона. Раз приложение всё равно
есть, сайт открывается через него, а не через Chrome. Это не «до кучи»:

- токен агента перестаёт вводиться руками — сайт отдаёт его приложению сам;
- кнопка «Показать экран» (ТЗ 3) живёт на странице сайта, а не в нативном
  экране, значит нативного кода почти нет;
- правки сайта приезжают обычным деплоем, **без пересборки APK**.

Внутри — WebView *(встроенный в Android движок Chromium: окно браузера
прямо внутри своего приложения)*.

## Что сделать в приложении

- WebView на весь экран, `https://vitazgio.ru`, старт сразу на `/cabinet`.
- Значок и имя — как у нынешней PWA: знак VG на тёмном (`static/icons/vg.svg`,
  готовые png рядом), имя «Vitaz Gio».
- Нативной разметки ровно два куска: заглушка «нет связи» с кнопкой
  «повторить», когда сайт не отвечает, и тонкая полоска состояния агента
  поверх WebView.
- Служба из ТЗ 1 заодно держит WebView живым в фоне — это то, что позволит
  плееру играть с выключенным экраном.
- Самообновление: при запуске сверить свою версию с `/app`, предложить
  обновиться (`REQUEST_INSTALL_PACKAGES`). Магазина нет, иначе каждая
  правка нативной части — «зайди, скачай, поставь руками».

## Ловушки WebView — он НЕ Chrome

Голый WebView теряет то, что у PWA работает само. **Все пункты закрыть
сразу, не «потом»** — иначе приложение выйдет хуже нынешней PWA и хозяин
справедливо вернётся в Chrome.

| Что отваливается | Чем чинится |
|---|---|
| «Поделиться» → дроп (сейчас `share_target` из манифеста) | `intent-filter` на `ACTION_SEND`/`SEND_MULTIPLE` → отправка в `/share-target` |
| Выбор файлов: `+` в дропе, загрузка в `/files`, скрепка и фото в `/ai` | `WebChromeClient.onShowFileChooser` |
| Любое скачивание: файл из дропа, zip папки, APK с `/app` | `DownloadListener` + `DownloadManager` |
| Кнопка «назад» закрывает приложение вместо шага по истории | `OnBackPressedCallback` + `webView.canGoBack()` |
| Сессия слетает после перезапуска | `CookieManager.flush()`, постоянные куки |
| Камера, микрофон со страниц | `WebChromeClient.onPermissionRequest` |
| Отдельное окно плеера `/player/pop` | `setSupportMultipleWindows` + `onCreateWindow` |
| Внешние ссылки открываются внутри оболочки | свой `shouldOverrideUrlLoading`: чужой домен — в системный браузер |

Чего в WebView не будет и не надо: установки PWA, пуш-уведомлений (на сайте
их и нет — ни `pushManager`, ни VAPID), автозаполнения паролей Chrome.
Service worker (`/sw.js`) внутри WebView работает, но приём «Поделиться»
идёт мимо него — через `intent-filter` выше.

## JS-мост и токен

- На сайте: `/api/phone/token` за `login_required` — отдаёт секрет
  устройства. Хозяин вошёл в кабинет внутри приложения → мост забрал токен
  → `EncryptedSharedPreferences`. Отзыв — с сайта, а не сменой общего
  пароля для всех.
- **Мост — самое опасное место всей затеи.** Он даёт JavaScript страницы
  нативные возможности телефона, а на сайте есть места, где показывается
  пришедший извне текст (чаты нейронки, имена файлов в дропе). Поэтому:
  - мост доступен, только когда в WebView открыт `https://vitazgio.ru`;
    origin проверяется на КАЖДОМ вызове, не один раз при старте;
  - методов три-четыре и все узкие: `getStatus`, `saveToken`, позже
    `startScreen`/`stopScreen`. Никакого «сделай, что скажут» — то же
    правило, что в протоколе: shell отсутствует как класс;
  - захват экрана всё равно спрашивает системное подтверждение, так что
    даже пробитый мост не включит трансляцию тихо.

## Приёмка (делает хозяин, минут пять — не ночь)

1. Открыл приложение — сразу кабинет, вход не слетел после перезапуска
   телефона.
2. «Поделиться» фоткой из галереи → выбрал Vitaz Gio → файл лежит в папке
   Download дропа.
3. На `/files/<ip>` скачал папку zip-архивом — файл в загрузках телефона.
4. В `/ai` скрепка открыла выбор файла, фото прикрепилось.
5. Музыка с `/music` играет при выключенном экране.
6. Кнопка «назад» ходит по истории сайта, а не закрывает приложение.

Принято — **удалить старую PWA с телефона**, чтобы не было двух одинаковых
значков VG с разными сессиями. На сервере PWA остаётся навсегда: она нужна
на ПК и чужих устройствах.
