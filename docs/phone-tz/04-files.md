# ТЗ 4. Файлы телефона под готовой страницей /files

**Начинать после приёмки ТЗ 3.** Вторая по важности цель: забрать фото с
телефона на ПК и закинуть фильм с ПК на телефон, **не доставая телефон из
кармана**.

## Главное правило: страница НЕ переделывается

`/files` и её API уже написаны, работают по SFTP и покрыты тестами
(`blueprints/files.py`, `templates/files.html`, `tests/test_files.py`).
Для телефона меняется **только транспорт под ними**: вместо paramiko
команды уходят агенту в сокет.

Внутри `blueprints/files.py` развести два бэкенда за общим интерфейсом:
`list / read / write / mkdir / rename / delete`. SFTP-бэкенд — нынешний код
как есть, агентский — новый. Страница, её вёрстка и её тесты остаются
нетронутыми; это проверка того, что интерфейс выбран правильно.

Бонусом бесплатно достаётся то, что на странице уже сделано: zip папки
целиком, перенос файла прямо в дроп кнопкой VG, прогресс загрузки,
переиспользование соединения без повторного пароля.

## Что сделать в приложении

- Разрешение `MANAGE_EXTERNAL_STORAGE` («доступ ко всем файлам»). Выдаётся
  один раз в настройках Android и живёт постоянно — **участия человека при
  работе не требует**, в отличие от захвата экрана.
- Операции: список папки, отдать файл, принять файл, создать папку,
  переименовать, удалить.
- Передача **кусками**. Файл целиком в память не тянуть: с ПК полетят
  фильмы, телефон умрёт на первом же.
- После записи дёрнуть `MediaScanner` — иначе новое видео не появится в
  галерее до перезагрузки телефона.
- Ошибки отдавать внятным кодом (нет места, нет прав, нет файла), а не
  молчанием: страница уже умеет показывать их карточкой.

## Протокол (часть про файлы)

```
сайт  → агент  {"type":"ls","id":7,"path":"/storage/emulated/0/DCIM"}
агент → сайт   {"type":"ls.ok","id":7,"entries":[…]}
сайт  → агент  {"type":"put","id":8,"path":"…/Movies/film.mkv","size":1234}
               далее двоичные кадры: [id:4][кусок]
```

Первые 4 байта двоичного кадра — номер запроса, чтобы не путать ответы и
не гонять base64. Команды «выполни shell» в протоколе нет.

## Что сделать на сайте

- Агентский бэкенд в `blueprints/files.py` + маршрутизация: обычная машина
  → SFTP, MOBILA → агент.
- На `/netbird` у MOBILA кнопка файлов из «СКОРО» становится живой.
- `docs/routes-inventory.md`, если добавятся роуты.
- Тесты: тот же приём, что у фальшивого paramiko — фальшивый агент поверх
  временной папки. Проверить список, скачивание, загрузку кусками,
  переименование, удаление, обрыв соединения на середине.

## Ловушки, уже известные по SFTP-версии (не наступать заново)

- Скачивание отдаётся генератором с `application/octet-stream` — этого типа
  нет в `GZIP_TYPES`, иначе `compress_response` собрал бы весь поток в
  буфер и сожрал память.
- Имя при загрузке режется через `posixpath.basename`, чтобы `../` не увёл
  выше папки.
- Непустую папку с первого раза не удаляем: сервер отвечает
  `needs_recursive`, страница переспрашивает карточкой.
- Одно соединение из разных потоков — только под локом. У SFTP это
  `entry["io_lock"]`; у агента та же история, фоновые переносы живут
  параллельно запросам страницы.

## Приёмка (делает хозяин)

1. Телефон лежит с **выключенным экраном**, в кармане.
2. С ПК закинул фильм → он появился в галерее телефона.
3. Скачал фото с телефона на ПК.
4. Переименовал и удалил файл — сработало.
5. Ничего на телефоне нажимать не пришлось.

## Чего в этом задании НЕ делать

Управление жестами и звук — ТЗ 5 и ТЗ 6. Синхронизацию папок не делать
никогда: на телефоне 250 ГБ, нужен живой доступ, а не вторая копия.
