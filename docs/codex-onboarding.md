```python
TEMPLATE_DIR = Path(__file__).parent / "templates"

def _template(name):
    return (TEMPLATE_DIR / name).read_text(encoding="utf-8")
```

`.replace()`/`.format()` после, так и осталось, просто строка теперь

## Жёсткие правила (нарушать нельзя)

- **Не Jinja2.** Шаблоны — обычные текстовые файлы, читаются
  `_template()`, подстановки — тем же `.replace()`/`.format()`, что и
  раньше. НЕ `render_template()`, автоэкранирование Jinja сломает
  вставленный в HTML код (в них живой JS с `${}`/`{{ }}`-подобными
  последовательностями).
- **Один раздел плана — один маленький коммит.** Не смешивать разделы.
  Диф должен быть «функция переехала в файл + склейка регистрации»,
  никаких попутных правок «раз уж открыл».
- **Поведение не меняется байт в байт**: те же URL, методы, декораторы,
  mimetype, кэш-заголовки, ETag, редиректы, сессии. Если что-то не
  уверен — не трогай, отдельным вопросом.
- Общие хелперы переносить ТОЛЬКО вместе с разделом, которому они
  впервые понадобились (см. «Shared Helpers First» в
  `docs/blueprints-plan.md`) — не тащи всё разом заранее.
- Локальную переменную обработчика Escape нельзя называть `esc` —
  так называется глобальный html-экранировщик, конфликт даёт TDZ-баг
  (уже дважды ловили).
- `\n` внутри питоновской тройной строки — настоящий перенос строки,
  рвёт JS. Актуально, только если где-то остался HTML/JS прямо в
  `app.py` (проверить перед правкой).

## Как проверять на каждом шаге

```bash
python3 -c "import ast; ast.parse(open('app.py').read())"
```
Дальше — тест-клиентом Flask сравнить ответы старого и нового кода на
затронутых роутах (статус, тело, заголовки) — руками сверить, что
ничего не изменилось. После коммита — пуш и проверка, что деплой в
GitHub Actions зелёный (workflow «Claude auto-merge» → «Deploy»,
итоговый шаг реально стучится в `http://172.17.0.1:5000/` на VPS —
если он прошёл, сайт точно живой, не только собрался).

Число роутов до и после переноса должно остаться **127** — если
меньше или больше, что-то потерялось или задвоилось.
