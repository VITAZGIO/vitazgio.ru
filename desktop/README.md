# Vitaz Gio для Windows

Windows 10/11 x64, Electron. Название и знак VG совпадают с Android:
`static/icons/maskable-512.png` — тот же исходник Android adaptive icon.
Установщик: `dist/vitazgio-windows-0.1.0-x64.exe`.

## Как пользоваться

1. Установить EXE и войти в свой кабинет. Компьютер автоматически появится
   на `/apps`, токен устройства хранится через Windows DPAPI (Electron safeStorage).
2. Музыка играет в одном постоянном окне. Кнопка вынесения показывает его
   поверх остальных окон, без рамки. За заголовок можно перетащить, за край
   изменить размер. Крестик прячет окно; воспроизведение остаётся в приложении.
3. Закрытие основного окна оставляет значок в трее. «Выход» в меню трея
   завершает приложение. Автозапуск включён по умолчанию, отключается в настройках.
4. В трее → «Настройки и доступ к ПК» выбрать монитор и включить доступ.
   Мышь/клавиатура разрешаются отдельным переключателем. Первоначально оба
   разрешения выключены. После включения подтверждать каждый сеанс не нужно.
5. С любого браузера или Android-оболочки открыть `/desktop` (ссылка есть
   на `/apps` и `/netbird`), ввести суточный пароль консоли и подключиться.
   Ctrl+Alt+Shift+F12 на компьютере выключает доступ. Отзыв на `/apps`
   закрывает соединение при следующей проверке (обычно до двух секунд).
6. «Проверить обновления» есть на `/apps`, в настройках и трее. Если EXE
   новее, приложение скачивает его в системную папку «Загрузки» и проверяет
   SHA-256 GitHub asset. Установщик запускается вручную, файлы пользователя
   не перезаписываются. Авторизация и настройки сохраняются при обновлении.

Страницы и основная логика по-прежнему на сайте. F5/Ctrl+R обновляют основной
сайт и простаивающий агент без прерывания музыки. Код окна плеера обновляется
при следующем запуске приложения; скачивать EXE для правок сайта не нужно.
Изменение нативного моста, движка Chromium или функций Windows требует EXE.

## Совместимость с браузером

`window.VGDesktop` предоставляется только из preload оболочки. Без него
`vg_player.js.tpl` использует прежний браузерный движок. Страницы сайта,
Android-агент, RDP/VNC/SSH и файловый менеджер сохраняют свои маршруты.
Просмотр Windows-экрана работает в браузере без установки приложения на
устройство зрителя. Приложение требуется на компьютере, экран которого смотрят.

## Экран и локальная сеть

`static/desktop-agent.js` работает в постоянном скрытом окне, загружается
с сайта. Захват — Electron desktopCapturer/getDisplayMedia, передача — WebRTC,
до 1920×1080, 30 кадров/с, целевой потолок 6 Мбит/с. Кодек выбирается WebRTC.
Мышь и клавиатура передаются по RTCDataChannel; нативный модуль `input.cjs`
принимает только ограниченные события, без команд оболочки. Изображение
масштабируется с сохранением пропорций, координаты учитывают масштаб Windows.

В одной локальной сети ICE может выбрать прямой LAN-путь. Сайт участвует
в авторизации, согласовании соединения и проверке доступа, но не пересылает
видео. Это пока **не офлайн-режим**: при потере управляющей связи захват
останавливается. На будущее нужны локальное обнаружение, сопряжение и
локальное согласование без VPS, плюс WebRTC-транспорт Android для прямого
видео телефон → ПК. Существующая трансляция Android сейчас остаётся прежней.

Через интернет прямой путь зависит от NAT/межсетевых экранов. По умолчанию
используется STUN `stun:stun.l.google.com:19302`, TURN не развёрнут. При
необходимости серверу задаётся `DESKTOP_ICE_SERVERS` — JSON-массив стандартных
RTCIceServer (urls, username, credential). Без TURN в некоторых сетях
соединение не установится; существующий RDP остаётся доступен. Интерфейс
показывает прямой/relay путь, RTT, разрешение и частоту кадров.

Работа с UAC, защищённым рабочим столом и вводом в повышенные процессы не
поддерживается обычным пользовательским приложением. При блокировке Windows
текущий сеанс останавливается. Скорость на разных машинах и сетях требует
практических замеров; более низкая задержка, чем у RDP, не гарантируется.

## Разработка и сборка

Node.js 24, pnpm 11.19.0, Python + Pillow для преобразования существующего
значка. Из корня репозитория:

```powershell
python desktop/scripts/icon.py
cd desktop
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm test
pnpm start
pnpm dist
```

Зависимости закреплены в package.json и pnpm-lock.yaml. `dist` и node_modules
не коммитятся. Установщик пока не имеет доверенной издательской подписи.

`.github/workflows/windows.yml` собирает EXE на Windows и публикует отдельный
тег `windows-vX.Y.Z`. Для нового нативного релиза нужно увеличить version в
package.json. Windows-релизы имеют `make_latest: false`, чтобы не подменять
Android-релиз для существующего `/api/app/pull`. Проверка Windows ищет теги
только `windows-v*`, а не общий `/releases/latest`.

После локальной разработки необходимо опубликовать изменения сайта и первый
Windows-релиз. Сборка EXE не деплоит сервер автоматически. Dockerfile копирует
blueprints; каталог desktop в Docker-контекст не попадает.

## Проверки

- `python -m pytest -q` — сайт и агент, копия данных во временной папке.
- `pnpm test` — изоляция native bridge, версии релизов, прокси плеера.
- `electron tests/smoke-main.cjs` — настоящий Electron с временным профилем
  и перехваченными HTTPS-запросами. Проверяет непрерывную музыку при навигации,
  единственность окна, always-on-top, настройки, целостность обновления и
  прямой локальный видеосеанс и доставку ввода в подменённый драйвер. По
  умолчанию видео тестовое (холст), чтобы проверка работала и при заблокированной
  Windows. `VG_SMOKE_CAPTURE=1` включает проверку настоящего захвата экрана.
  Реальный ввод не выполняется, системный автозапуск не меняется.

Серверные signalling-сессии хранятся в памяти одного Flask-процесса, как и
существующий телефонный реестр. Для нескольких workers понадобится общее
хранилище/координатор. Перезапуск сайта завершает активные сеансы.
