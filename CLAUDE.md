# vitazgio.ru — память проекта

Личный сайт Виталия (VITAZGIO). Один файл `app.py` (~15 тыс. строк) на Flask,
HTML/CSS/JS живут строками прямо в нём. Деплой: пуш в ветку `claude/**` →
GitHub Action «Claude auto-merge» → main → «Deploy» (домашний раннер по SSH
через NetBird на VPS в Амстердаме, `docker compose up -d --build web`).

Ветка разработки: `claude/project-overview-2mnq1j`.

## Как проверять (важно)

- Питон: `python3 -c "import ast; ast.parse(open('app.py').read())"`.
- Встроенный JS: `scratchpad/jscheck.py` — вытаскивает скрипты со всех
  страниц и гоняет `node --check`. **Обязательно** после правок шаблонов.
- Ловушка: `\n` внутри питоновской строки `"""..."""` становится настоящим
  переносом и рвёт JS. В шаблонах писать `\\n`. Дважды из-за этого падал дроп.
- Живая проверка: Playwright + Chromium
  `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`,
  `NODE_PATH=/opt/node22/lib/node_modules`. Локальный запуск —
  `scratchpad/run.sh` (пароль кабинета `testpass`).

## Скорость: что уже сделано (не откатывать)

Замеряли — сервер отдаёт страницу за 2-3 мс, то есть бэкенд ни при чём,
переписывать движок незачем. Тормозил объём.

- **gzip на ответах** (`compress_response`, after_request). Страницы — это
  HTML со встроенными CSS и JS, кабинет весил 142 КБ; текст жмётся вчетверо
  → 32 КБ. Уровень 6: девятка выигрывает 0.2 КБ, а стоит втрое дороже.
  **Что обходим и почему** (ломать нельзя):
  — `text/event-stream` и вообще генераторы (`is_streamed` без
    `direct_passthrough`) — это SSE-чат нейронки, сжатие копило бы буфер и
    живая печать превратилась бы в один рывок в конце;
  — `send_file` с Range: у файлов `is_streamed` ТОЖЕ True, поэтому одного
    флага мало — различаем по `direct_passthrough`. Музыку/видео спасает и
    проверка типа (audio/* и video/* не в списке), и лимит `GZIP_FILE_MAX`;
  — не 200 (206 Partial, 304 Not Modified), уже сжатое, мелочь до 1 КБ.
  Проверено: перемотка музыки (206 + точные байты), файл дропа побайтово
  (SHA-256 сошёлся), бэкап-zip валиден, «Стоп» в чате работает.
- **Кэш статики**: `/static/*` отдавался с `no-cache` (Flask ставит его сам,
  поэтому именно перезаписываем, `setdefault` молчал бы) → сутки, как у
  уже настроенных `/icon-*.png`. Плюс SVG теперь ещё и жмётся втрое.
- **xterm и guacamole — по требованию** (`window.vendorReady`). Раньше 350 КБ
  библиотек ехали на КАЖДЫЙ заход в кабинет, хотя нужны только когда реально
  открываешь консоль или удалённый стол. Теперь их тянет `openTerminal` /
  `openRdp` при первом открытии, с тем же запасным CDN. Загруженное
  кэшируется в `done[]`, повторно не грузится.
  Итог по кабинету: **533 КБ → 49 КБ** по сети.
- Страницу `/claude` намеренно не трогали: там терминал и есть смысл
  страницы, а `defer` и так не блокирует отрисовку.

## Что сейчас в работе / решено

### Вкладка Claude (кабинет → /claude)
Готова как ЗАГОТОВКА, залита (коммит 3a20c01). Разговор с консольным
помощником через сайт: браузер → WebSocket `/ws/claude` → SSH (paramiko) →
tmux → команда. Тот же канал, что у консоли кабинета. Вкладки = сессии tmux
(`vg-1`, `vg-2`…), переживают закрытый браузер. Пускает пароль кабинета +
суточный пароль консоли. В коде НЕТ ничего специфичного для Claude —
запускает то, что в `CLAUDE_BIN`, так что туда встанет любой консольный агент.
Пока `CLAUDE_HOST` не задан в .env — страница висит безвредной заглушкой.
Настройка: `CLAUDE_HOST` (машина из NetBird с SSH), `CLAUDE_DIR`, `CLAUDE_BIN`.
Не доделано: автоподхват после «отцепиться», прикрепление фото, вход по ключу.

### Музыка /music — избранная папка (звезда)
Треки разложены по папкам, корень пуст — поэтому фонотека при заходе
казалась пустой. Теперь любую папку можно пометить **звездой** (кнопка на
плитке папки, только у хозяина); избранная одна на всю фонотеку (ставишь
новую — старая гаснет, чистится в `music_folder_patch_api` при `fav:true`).
Что она даёт: (1) `/music` при первом открытии сразу заходит в избранную
папку (`openedFav` + `data.fav_folder`), а не в пустой корень; (2)
`/api/player/tracks` (виджет и общий движок) и мини-плеер кабинета
(`load()` в `cabinet`, фильтрует `/api/music` по поддереву избранной)
играют **только** её содержимое с подпапками. Нет избранной — вся
фонотека, как раньше (и папка MUSIK из дропа добавляется только тогда).
Флаг `fav` живёт в `music_folders[id]`, отдаётся в `/api/music`
(`fav_folder` + `fav` у каждой папки). Тест — `scratchpad` (звезда,
переключение, фильтрация player/tracks и мини-плеера). Корневая крошка —
«Вся музыка».

### Дроп — совпадение имён при загрузке (как в проводнике)
Файл с уже занятым в этой папке именем спрашивает карточкой (`askConflict`,
в стиле сайта, не системная): **Сохранить оба** (дописывает `(2)`, `freeName`),
**Заменить** (старое уходит в корзину через `/api/drop/op` op=delete, новое
встаёт под тем же именем), **Пропустить**. Галочка «Применить ко всем»
запоминает выбор на остаток пачки (`forAll`). Проверка совпадений — по
`items` текущей папки (загрузка всегда в текущий `parent`); занятые имена
копим в `taken`, чтобы файлы одной пачки не занимали имя повторно. Ловушка,
которую поймали: локальную переменную-обработчик Escape нельзя звать `esc` —
так зовётся глобальный html-экранировщик, а он нужен выше при сборке
разметки диалога (иначе TDZ «Cannot access esc before initialization», и
диалог не появляется). Тест — `scratchpad/dropconflict.js`.

### Дроп → MUSIK — создание папок и загрузка музыки
Папка MUSIK в дропе не хранит своё, а показывает саму фонотеку (папки с
id `mf_`, треки с `mt_`). Из-за этого «Новая папка» внутри MUSIK не
работала: `drop_folder_create` заводил обычную папку склада дропа, а MUSIK
показывает `music_folders` — созданная папка просто не появлялась («создал,
а её нет»), а с `mf_`-родителем и вовсе улетала в корень дропа. Теперь при
`parent == "musik"` или `parent` c префиксом `mf_` создаётся НАСТОЯЩАЯ папка
фонотеки (`music_folders`, ответ отдаёт `id` уже с `mf_`), с проверкой
глубины `MUSIC_MAX_DEPTH`. Так папка, заведённая в дропе, — та же, что видит
плеер и страница `/music`; загрузка в неё уже роутилась в фонотеку
(`_drop_music_take` по `mf_`-родителю), трек ложится именно в эту папку.
Проверено curl: папка в MUSIK видна, вкладывается, крошки верные, `/api/music`
показывает её с правильным `parent`.

### DIY /diy — оставили один вид листания (Кладка)
Раньше было пять видов (Сетка/Барабан/Кладка/Веер/Соты) с переключателем
`#modes` и памятью выбора на полку (`localStorage.vgDiyViews`). Раньше уже
чинили баг вёрстки Кладки (JS-masonry вместо сломанного CSS column-count),
но хозяин уточнил: оставляем только сам вид Кладка, остальные четыре убрать
совсем, а не просто оставить переключателем. Убрано: переключатель `#modes`
и вся его CSS, `layFan`/`layDrum`/`relay`/`step`/`hauling` (горизонтальное
перетаскивание лентой — было нужно только барабану и вееру), `.rail`
(полоса хода барабана), ветка сот в `drawGrid()`, CSS-блоки `.m-grid`/
`.m-drum`/`.m-fan`/`.m-hex`, поле `view` у `DIY_THEMES` (раньше — вид по
умолчанию для тематики). Кладка — теперь единственная и безусловная
раскладка, `mode`/`MODES`/`viewOf`/`rememberView` тоже убраны как лишние.
Тест — `scratchpad/diy.js` (переключателя нет, класс сетки всегда
`m-mosaic`, кладка не ломается при смене полки).

### Музыка /music — избранная папка (звезда)
Виджет один на весь сайт (звук общий, `<audio>` живёт в модуле, а не в
странице), едет между страницами через `localStorage`, между вкладками
синхронизируется через `BroadcastChannel("vgplayer")`.
- **Баг «стопается при переключении вкладок»**: `resume()` на каждой новой
  странице/вкладке безусловно запускал `audio.play()`, если в
  `localStorage` было `playing:true` — а это правда, когда музыка играет
  в УЖЕ ОТКРЫТОЙ другой вкладке. Новая вкладка начинала параллельный
  голос, тот бродкастил `"play"`, и по правилу «одна вкладка играет,
  остальные молчат» ИСХОДНАЯ вкладка сама себя ставила на паузу — то
  есть просто открыть сайт во второй вкладке обрывало музыку в первой.
  Исправлено: перед автовключением `resume()` спрашивает через
  `BroadcastChannel` («ping») — не играет ли уже кто-то — и ждёт «pong»
  ~220мс; если ответили, эта вкладка не лезет со своим звуком.
- **Уровень громкости** — ползунок `data-volbar` в теле виджета (было
  только перемотка трека, без громкости); мьют — клик по значку
  громкости, помнит прошлый уровень. Использует уже существовавший
  `api.volume()`.
- **«Вынести» плеер — переделано на настоящее отдельное окно.** Первая
  версия использовала Document Picture-in-Picture: красиво (окно без рамок,
  поверх всех окон), но окно живёт вместе со вкладкой-открывашкой — а сайт
  многостраничный, и переход по нему на другую страницу заново грузит
  вкладку, что закрывает и PiP-окно, и звук. Ровно это и было жалобой
  «музыка лагает, вкладку открыл — всё зависло»: PiP не переживал обычную
  навигацию по сайту. Теперь `data-pip` делает `window.open()` на
  `/player/pop` — отдельный маленький HTML (флаг `window.VGP_POPUP = true`
  перед `<script src="/vg-player.js">`), тот же движок, просто всегда
  развёрнут на весь вьюпорт окна (класс `vgp-pip`, переиспользован из
  старой PiP-раскладки) и не сворачивается. Это окно НЕ привязано к
  вкладке-открывашке — переходы по сайту в исходной вкладке его не
  трогают. Эстафета передачи звука: `popOut()` ставит `audio.pause()` в
  исходной вкладке (запоминает точную секунду через `save()`) и тут же
  перезаписывает `playing:true` в `localStorage`, чтобы новое окно
  подхватило именно с этого места, а не с паузы — ловушка: событие
  `pause` от этого же `audio.pause()` приходит асинхронно и иначе
  перезаписало бы `playing` обратно на `false` позже нашей ручной записи,
  поэтому на время передачи (`quiet`, сбрасывается через 300мс)
  обработчик `pause` не зовёт `save()`. Крестик (`data-remove`) внутри
  самого окна закрывает именно его (`window.close()`), а не прячет виджет
  на сайте. Маршрут `/player/pop` под паролем кабинета (`@login_required`),
  как и `/music`.
- **Кнопки, которые хозяин реально нажимает, вели НЕ туда** — из-за этого
  «вынести из браузера» не работало, сколько ни чини сам вынос. Кнопка ⧉ в
  панели «Аудио» кабинета (`#pl-pop`) и кнопка на `/music` звали
  `VGP.open()`, то есть показывали виджет ПОВЕРХ страницы — никакого окна
  не появлялось, хотя значок ⧉ обещает именно окно. Обе переведены на
  `VGP.popOut()` (наружу выставлен из движка, внутри зовёт `openInWindow`),
  подписи честные: «Вынести плеер в отдельное окно браузера» / «Вынести в
  окно». Сам виджет по-прежнему включается автоматически, если его когда-то
  включали (`vgPlayerOn`), и у него своя ⧉ и свой крестик.
- **Баг «зависает при перелистывании вкладок» — музыка умирала от быстрых
  переходов.** `save()` писал в память `playing: !audio.paused`, то есть
  СИЮМИНУТНОЕ состояние звука. Но на только что открытой странице звук
  ещё не стартовал: трек грузится, а автоподхват вдобавок ждёт ответа
  опроса вкладок. Ушёл со страницы в эту щель — `pagehide` сохранял
  `playing:false`, и следующая страница честно не поднимала музыку. Чем
  быстрее листаешь, тем вернее обрыв. Теперь в памяти живёт НАМЕРЕНИЕ
  (`wantPlay`), а не факт: `resume()` поднимает его сразу, ещё до загрузки
  трека; снимается оно только настоящей паузой (человек нажал, трек
  кончился), а служебные паузы — передача звука окну и уступка другой
  вкладке — помечены флагом `quiet` и намерение не трогают.
- **Опрос вкладок убран с дороги.** `askIfPlaying()` (220мс) стоял под
  `await` ДО постановки трека, поэтому каждый переход по сайту замирал на
  четверть секунды. Теперь трек и позиция встают сразу, а решение
  «включать ли звук» доезжает следом (`goIfAllowed`); чтобы припозднившийся
  ответ не перебил человека, есть флаг `userActed`.
- **Кнопка окна «перестала работать вообще» после деплоя — виноват кэш
  движка.** `/vg-player.js` отдавался с `private, max-age=300` и БЕЗ ETag.
  После заливки страница приезжает свежая (её кнопка зовёт `VGP.popOut()`),
  а движок браузер ещё пять минут берёт из кэша — старый, где `popOut` нет.
  Результат: `TypeError: window.VGP.popOut is not a function`, кнопка молча
  не делает ничего (раньше она звала `open()`, который в старом движке был,
  поэтому хоть виджет показывался). Починено в два слоя: (1) движок теперь
  `private, no-cache` + ETag по md5 самого текста и `make_conditional` —
  браузер каждый раз спрашивает, при совпадении получает пустой 304, так что
  трафика столько же, но устареть движок больше не может; (2) обе кнопки
  (`#pl-pop` в кабинете и `.popout` на `/music`) умеют запасной путь — если
  `VGP.popOut` почему-то нет, зовут `window.open("/player/pop", …)` сами.
  Урок: любой РАЗДЕЛЁННЫЙ на страницу и скрипт контракт ломается кэшом,
  если у скрипта нет ни версии в адресе, ни перепроверки.
- **Баг «свернул окно — не развернуть».** В вынесенном окне работала кнопка
  «свернуть»: кружок растягивался на весь вьюпорт (`.vgp-pip` шире по
  каскаду задаёт 100%×100%), а `.vgp-folded` прятал тело виджета вместе со
  всеми кнопками. Развернуть было нечем — обычно свёрнутый кружок
  разворачивают тычком в него, но обработчик перетаскивания в окне выходит
  сразу (`box.classList.contains("vgp-pip")`). Теперь `setFolded` в окне —
  пустышка, а кнопка «свернуть» там скрыта совсем (`.vgp.vgp-pip
  [data-fold]`). Заодно окно не наследует свёрнутость виджета с сайта.
- **«Без рамок и поверх всех окон» — только Chrome/Edge, и это не наша
  недоделка.** Рамку окна и адресную строку веб-страница убрать не может;
  Firefox показывает их у любого `window.open` принудительно и API для
  окна-поверх-всех не даёт вовсе. Единственный способ — Document
  Picture-in-Picture, он есть у Chrome/Edge. Ключевой урок прошлой попытки:
  такое окошко умирает вместе со СВОИМ открывашкой, поэтому звать его со
  страницы сайта нельзя — первый же переход его гасит. Теперь его зовёт
  окно `/player/pop` (кнопка ⧉ внутри окна, `onTop`): само окно никуда не
  переходит, поэтому плавашка переживает любую навигацию в основных
  вкладках. Где Document PiP нет — кнопка не показывается, чтобы не
  обманывать. Класс `vgp-top` = «уже поверх всех», прячет эту кнопку.
- **«Как в ютубе» — плавашка без рамок и поверх всех окон.** Разобрались,
  как это устроено у ютуба: его маленькое окошко на рабочем столе — это
  НАТИВНЫЙ видео-Picture-in-Picture браузера, а не обычное окно. Обычный
  `window.open` в Firefox принудительно показывает адресную строку (защита
  от поддельных окон), убрать её нельзя. Document PiP (наш живой html поверх
  всех окон) есть только у Chrome/Edge. А вот видео-PiP умеет и Firefox —
  но внутри может быть только ВИДЕО. Поэтому рисуем плеер (обложка-нота,
  название, исполнитель, полоса, время) на `<canvas>`, снимаем с него поток
  `captureStream()`, кладём в немой `<video>` и зовём
  `requestPictureInPicture()` — ровно механизм ютуба. Кнопка ⧉ внутри окна
  `/player/pop`: где есть Document PiP — отдаём живой виджет (`onTop`), где
  нет (Firefox) — видео-PiP (`videoPip`), выбирает `floatOnTop`/`canFloat`.
  Управление в видео-PiP — родные кнопки браузера (play/pause/дальше/назад
  через `mediaSession`); кликабельного списка треков там нет и быть не может
  (внутри одни пиксели) — это железное ограничение, честно объяснено хозяину.
- **Выбор папок в списке окна.** Список треков (`drawRows`) теперь
  двухуровневый: если папок больше одной — сперва папки (иконка + название +
  сколько треков, склонение трек/трека/треков), тычок заходит внутрь, «‹ Все
  папки» возвращает назад. Данные о папке уже были в каждом треке
  (`t.folder`), поэтому ни нового API, ни прав не понадобилось — просто
  группируем очередь. Ловушка, которую поймали: счётчик писали в
  `querySelector("span")`, а первым span в строке была иконка `.fico` —
  целимся в `.n span`. И авто-подсветку играющего трека (`paintFns`)
  включаем только когда РЕАЛЬНО показаны треки (есть `[data-i]`), иначе в
  обзоре папок `drawRows` дёргался бы каждый кадр.
- **Окончательно: кнопки открывают НЕЗАВИСИМОЕ окно (popOut).** Хозяин
  метался, но выбрал твёрдо: важнее, чтобы плеер не закрывался и не лагал
  при листании вкладок сайта. Прямая плавашка (видео-PiP) это дать не может
  — она привязана к странице и гаснет на первом переходе. Поэтому кнопки на
  сайте (⧉ в кабинете, «Вынести в окно» на `/music`) зовут `popOut` →
  отдельное окно `/player/pop`: свой звук, эстафета (сайт встаёт, окно
  продолжает с той же секунды), переживает любую навигацию. Плавашку «как в
  ютубе» даёт кнопка ⧉ уже ВНУТРИ окна (`floatOnTop`) — и она там тоже
  переживает переходы, ведь само окно никуда не идёт. `floatOut` в движке
  остался, но кнопки на него больше не смотрят.
- **(было) Один клик до плавашки — кнопки снова на floatOut.** Хозяин: «опять
  надо в окне открывать чтобы в окне открыть». Кнопки на сайте (⧉ в
  кабинете, «Поверх окон» на `/music`) зовут `floatOut`: СРАЗУ финальная
  плавашка поверх всех окон, без промежуточного `/player/pop` — Document
  PiP в Chrome, видео-PiP как у ютуба в Firefox. Если видео-PiP не пустили
  (нет жеста/заблокирован) — запасной путь в отдельное окно
  (`videoPip().then(ok => !ok && openInWindow())`). Компромисс честный:
  прямая плавашка закрывается при переходах по самому сайту (видео-PiP
  привязан к документу страницы), но музыка при этом не рвётся (`wantPlay`
  продолжает её на новой странице), а плавашку видно снова одним кликом.
  Кому нужна выживающая при навигации — `/player/pop` остался (`popOut`),
  и из него ⧉ (`floatOnTop`) даёт ту же плавашку, но переживающую переходы.
- **(было) Отдельное окно снова главное — плавашка «как в ютубе» дохла от навигации.**
  Прямой видео-PiP из страницы сайта закрывается при первом же переходе по
  сайту (видео-PiP привязан к своему документу — уходишь со страницы, окно
  гаснет). Хозяин: «плеер лагает и закрывается, когда листаю вкладки». Поэтому
  кнопки на сайте (⧉ в кабинете, «Вынести в окно» на `/music`) снова открывают
  НЕЗАВИСИМОЕ окно `/player/pop` (`popOut`): у него свой звук, оно не
  перезагружается от навигации, музыка на сайте встаёт, а в окне продолжается
  с той же секунды. «Как в ютубе» (без рамок, поверх окон) — кнопка ⧉ уже
  ВНУТРИ окна (`floatOnTop`): оттуда видео-PiP переживает навигацию, потому что
  само `/player/pop` никуда не переходит. Итог честного компромисса Firefox:
  независимость важнее хромлесс, поэтому база — отдельное окно, а хромлесс —
  один клик внутри него.
- **Выбор папки музыки — из ПОЛНОГО дерева, а не из текущей очереди.**
  Прошлый список группировал только загруженные треки: если очередь в одной
  папке — выбора нет. Теперь `/api/player/tracks` отдаёт `folders` (всё дерево
  фонотеки) + `fav`, и принимает `?folder=<id>` (папка с подпапками) либо
  `?folder=__all__` (вся музыка вопреки избранному). В списке (`☰`) сверху
  секция «Папки»: «Вся музыка» и каждая папка с отступом по глубине; тычок
  грузит её (`choosePick` → `fetchList(true, pick)`), треки ниже обновляются,
  активная папка подсвечена. Подсветку играющего трека теперь двигаем на
  месте, без полной перерисовки — иначе список с папками прыгал бы каждый кадр.
- Тесты: `scratchpad/popfolders.js` (окно не сворачивается, выбор папок из
  дерева — Баллады/Рок-с-подпапкой/Вся музыка, подсветка активной, игра трека),
  заход/выход/выбор трека, кнопка видео-PiP заводится без ошибок),
  `scratchpad/popfold.js` (в окне нельзя свернуть и запереть плеер),
  `scratchpad/player.js` (громкость, мьют, два таба, «вынести»,
  крестик), `scratchpad/flip.js` (семь быстрых переходов подряд — музыка
  жива, намерение в памяти не сбивается), `scratchpad/popbtn.js` (кнопки ⧉
  в кабинете и на `/music` открывают именно `/player/pop`),
  `scratchpad/lag.js` (замер: трек встаёт за 0 мс, эстафета в окно).
  `/vg-player.js` входит в `scratchpad/jscheck.py` отдельным пунктом —
  раньше как внешний скрипт (`<script src=...>`) вообще не проверялся;
  туда же добавлен `/player/pop`.

### Страница «Нейронки» /neuro + /ai — чаты через OpenRouter — СДЕЛАНО
DeepSeek у OpenRouter в 2026 сняли с бесплатных моделей целиком, поэтому
перешли на другие. Одна карточка «Нейронки» в кабинете (нейтральный
акцент #9aa3c9, без фиолетового — раньше иконка карточки и градиент
MiniMax были случайно фиолетовыми, хотя цвета сети розовый/зелёный/
оранжевый; поправлено). `/neuro` — обёртка с тремя вкладками сверху,
каждая показывает `/ai?m=<модель>` в своём iframe и красится в свой цвет:
**MiniMax** (`minimax/minimax-m3:free`, розовый `#ff3d9a`/`#ff8fc4`,
multimodal — умеет фото), **NVIDIA** (`nvidia/nemotron-3-ultra-550b-a55b:free`,
зелёный `#76c900`/`#39ff14`), **Claude** (оранжевый `#d97757`/`#f0a184`).
Модель у каждой вкладки зашита в самой странице (`/neuro`), в `.env` она
не нужна — только `OPENROUTER_KEY`. Если модель вкладки ответила ошибкой
(сняли/переименовали/упёрлись в лимит), сервер сам перебирает список
живых бесплатных (раз в 15 мин подтягивает каталог `/api/v1/models`,
берёт всё с ценой 0).

Функционал чата на /ai:
- Список прошлых чатов слева, **папки** (создать/переименовать/удалить —
  удаление папки не трогает чаты, просто выкладывает их обратно),
  **переименование чата** (карандаш на строке), **перенос между папками**
  (иконка-папка на строке → меню), **закрепление** (булавка → своя секция
  «Закреплённые» сверху списка), **поиск по чатам** (фильтр по заголовку,
  крестик очищает). Сайдбар шире прежнего (317px, было 264) и **сворачивается**
  — кнопка внутри самого сайдбара (не в общей шапке справа, где она была
  нелогично оторвана от списка, который слева), а разворачивается назад
  плавающей кнопкой у левого края поверх чата (видна только когда список
  свёрнут — сам сайдбар в этот момент `width:0`, до кнопки внутри него не
  дотянуться). Состояние в `localStorage.aiSidebarCollapsed`.
- Подтверждения/ввод — **свои карточки** (`uiConfirm`/`uiPrompt`/`uiToast`),
  не системные `confirm()`/`prompt()`/`alert()` браузера: удаление чата и
  папки, создание папки, «В блокнот», предупреждение про большой PDF —
  всё в теме страницы (тёмная карточка, акцент текущей сети). Раньше
  системные диалоги торчали чужеродным окном браузера.
- На каждом сообщении (и своём, и ответе) — **кнопка «Копировать»**,
  на ответах ещё **«В блокнот»** (спрашивает название, переносит текст
  ответа в заметку через уже существующий `/api/notebook/entry`) и, на
  самом последнем ответе, **«Заново»** (перегенерировать — стирает
  последний ответ и просит модель заново тем же вопросом/фото/PDF,
  `POST /api/ai/chat/<id>/regenerate`).
- **Кнопка Стоп**: та же кнопка отправки, во время генерации превращается
  в квадрат-стоп (`AbortController` на fetch); то, что успело прийти,
  остаётся в чате и сохраняется — сервер ловит обрыв соединения как
  `GeneratorExit` в `finally` у `_ai_run_stream` и досохраняет частичный
  ответ, так что «Стоп» не роняет историю.
- Автозаголовок чата (`_ai_smart_title`) теперь долетает до сайдбара сразу
  первым кадром SSE-потока (`{"title": ...}`), а не только после
  перезагрузки страницы — иначе поиск по свежесозданному чату не находил
  его, пока заголовок ещё был «Новый чат» только на сервере.
- **Аватарка бота — и буквы, и ЦВЕТ — по модели, которая РЕАЛЬНО ответила
  на конкретное сообщение** (`m.model`, хранится в `data/aichat.json` на
  каждой ответной реплике), а не по вкладке, из которой сейчас открыт
  чат — раньше переключение вкладок MiniMax/NVIDIA/Claude меняло буквы
  на аватарках у СТАРЫХ сообщений (`avaFor(model)` вместо старой
  глобальной константы `AVA`), но кружок аватарки красился в
  `var(--ac)`/`var(--ac2)` — то есть в цвет ТЕКУЩЕЙ вкладки: открыл чат,
  где вперемешку отвечали MiniMax и NVIDIA, из вкладки NVIDIA — и подпись
  «MM» висела на зелёном кружке вместо розового. Добавлена `avColorFor`
  (свой `[ac,ac2]` для MM/NV, задаётся инлайн-стилем на `.av`) — теперь
  цвет аватарки не зависит от того, из какой вкладки открыт чат.
- Ответ потоком (SSE) с живой печатью + markdown (жирный, код, ссылки).
- Фото: браузер ужимает картинку, сервер шлёт vision-модели (для
  MiniMax уже сама умеет) и хранит в `data/aichat_img/`.
- **PDF**: отдельная кнопка-скрепка рядом с фото, до 8 МБ; текст
  вытаскивается на сервере через `pypdf` (`_ai_pdf_extract`, до 6000
  символов) и подкладывается в контекст на КАЖДОМ следующем ходе
  разговора (не только в момент прикрепления) — так что «а что там про
  X» на следующей реплике всё ещё видит документ. В чате — маленький
  значок с именем файла и на прикреплённом сообщении, и в композере
  перед отправкой.
- **Размышления (reasoning)** — у MiniMax и NVIDIA/Nemotron (проверка
  `_ai_wants_reasoning` по id модели) в запрос добавляется
  `"reasoning": {"enabled": true}`; поток размышлений приходит отдельным
  полем `delta.reasoning`/`delta.reasoning_content` (не смешивается с
  `delta.content`). Пока модель думает — над ответом раскрытый блок с
  текстом размышлений и тикающим таймером («Думает… N с»); на первом
  куске самого ответа блок сам сворачивается, подпись меняется на
  «Думал», таймер замирает на финальном числе — по клику на заголовок
  разворачивается обратно. Время до первого куска ответа считает сервер
  (`think_secs` в `_ai_run_stream`) и сохраняет вместе с текстом
  размышлений в сообщении (`reasoning`/`reasoning_secs` в
  `data/aichat.json`), отдаёт через `ai_chat_get` — при открытии чата
  заново блок так же на месте (свёрнут, с тем же временем). Кнопка
  «Копировать» на ответе размышления в буфер не тянет — берёт только
  `out.dataset.raw`, куда пишутся исключительно куски `delta.content`.
- Реплика юзера сохраняется СРАЗУ: лимит исчерпан — написанное не пропадёт.
- **Баг с остаточным фиолетовым/синим** (аватарка бота, пузырь своих
  сообщений, кнопка отправки, «Новый чат», скроллбары, ховеры) — чинили
  цвет вкладок раньше, но добрая половина мелких элементов на /ai
  по-прежнему была на хардкоженных `rgba(77,107,254,*)`/`rgba(139,123,255,*)`
  (старые синий/фиолетовый DeepSeek-цвета), а не на `var(--ac)`/`var(--ac2)`
  текущей сети. Заменено на `color-mix(in srgb, var(--ac) N%, transparent)` —
  этот же паттерн уже был в ходу на других страницах сайта.

Настройка на сервере (.env): только `OPENROUTER_KEY` обязателен.
`OPENROUTER_MODEL`/`OPENROUTER_VISION_MODEL`/`OPENROUTER_URL` — опционально.
Код: блок `# Нейросеть: чат с DeepSeek через OpenRouter` в app.py (роуты
`/neuro`, `/ai`, API `/api/ai/*`, `/api/ai/folder*`, `/api/ai/chat/<id>/regenerate`).
`requirements.txt` теперь тянет `pypdf`. Тесты: `scratchpad/aitest.js`,
`aifeat*.js` (копирование/папки), `aiimg2.js` (фото), `batch2.js`/`batch3.js`
(стоп/перегенерация/поиск/пин/сайдбар/PDF/аватарки), `reason.js`
(размышления — таймер тикает, сворачивается на ответе, не копируется,
переживает reload), фейковый OpenRouter — `scratchpad/fakeor.py` (слово
`stopme` в тексте — отвечает медленно, чтобы успеть нажать «Стоп» в
тесте; при `reasoning` в запросе сперва шлёт несколько `delta.reasoning`).
Не доделано (если захочет): выбор модели прямо со страницы (сейчас только
через вкладки /neuro), редактирование своей реплики.

## Ограничения, заданные хозяином (соблюдать)

- Себастьян: гости из сети могут болтать, но НЕ управлять домашними
  устройствами. Модель — только та, что уже в памяти видеокарты; новую не
  поднимать (видеопамять занята).
- Страница серверов /servers — публичная: без локальных IP, без публичного
  адреса VPS, без адресов NetBird.
- Пароль корзины дропа хранится хэшем (sha256), не открытым текстом.

## Незакрытое (зависит от хозяина, не от кода)

- `SEBASTIAN_OLLAMA=http://<ubuntu-vm>:11434` на сервере — иначе чат
  Себастьяна не работает.
- `BACKUP_TOKEN` — для внешнего домашнего бэкапера.
