# vitazgio.ru — память проекта

Личный сайт Виталия (VITAZGIO), Flask. Схема (задачи 1-40,
`docs/codex-refactor-plan.md` и `docs/structure-plan.md`, оба выполнены):
`app.py` — тонкий (создание приложения, конфиг, регистрация blueprint'ов,
запуск фоновых задач); `core/` — общая инфраструктура (вход, хранение,
чтение шаблонов), обычные модули, выполняются при импорте; `blueprints/` —
каждая фича своим файлом, импортирует нужное из `core/` и других
blueprint'ов напрямую, без фабричных простыней аргументов; `templates/` —
HTML/CSS/JS страниц, обычные текстовые файлы без Jinja2 (подстановки —
`.replace()`); `tests/` — проверки, гоняются в CI дважды (до слияния в
main и перед сборкой на VPS). Деплой: пуш в ветку `claude/**` → GitHub
Action «Claude auto-merge» → main → «Deploy» (домашний раннер по SSH через
NetBird на VPS в Амстердаме, `docker compose up -d --build web`).

**Подробная хроника решений и переделок (кто что чинил, что откатывали и
почему) — в `docs/history.md`.** Здесь только правила и текущее состояние.
**Правила совместной работы с ИИ (модель, эффорт, разбивка по инструментам,
как экономить лимиты) — в `docs/workflow.md`.** **Сказал «приложение на андройд
ретранслятор» (он пишет «ретронслятор») — это про своё Android-приложение
для экрана и файлов телефона, оно же оболочка-браузер для самого сайта,
ТЗ целиком в `docs/phone-access-plan.md`, читать оттуда и работать по
ступеням.**

## Инфраструктура VPS (Амстердам) — не трогать без причины

- `/etc/docker/daemon.json` на VPS **намеренно** содержит
  `"features": {"containerd-snapshotter": false}` (добавлено 2026-09-04).
  Без этого Docker хранит слои образов через containerd-снапшоттер —
  у него бывает необратимая порча метаданных («failed to stat parent:
  ... snapshots/N/fs: no such file or directory»), из-за которой падает
  ЛЮБАЯ сборка, включая `WORKDIR` на пустом месте, и **не лечится
  перезапуском Docker-демона** (метаданные битые на диске, не в памяти).
  Лечится только выключением этого режима (после — Docker сам качает
  слои заново под старым `overlay2`) либо переустановкой окружения.
  Если когда-нибудь понадобится этот режим включить обратно (например,
  ради каких-то его преимуществ) — сначала вспомнить про этот баг.
- **Побочка того же переключения**: containerd-снапшоттер — это отдельный
  от `overlay2` бэкенд хранения ВСЕХ контейнеров, не только образа сайта.
  Переключение на `overlay2` отвязало от Docker все контейнеры, что были
  созданы под старым бэкендом и не входят в `docker-compose.yml` этого
  репозитория: `guacd` (входит, но не был пересоздан заодно с `web` —
  почини через `docker compose up -d` без `--build`), а также два ЧУЖИХ
  для этого репо стека — `/root/npm/docker-compose.yml`
  (nginx-proxy-manager, там реверс-прокси для `*.vitazgio.ru`, данные в
  `./data`+`./letsencrypt`, не в docker volume) и
  `/root/socks-stack/docker-compose.yml` (`microsocks`+`cloudflared`,
  отдельный приватный SOCKS-туннель, к публичному сайту отношения не
  имеет). Если после следующего переключения бэкенда/массового рестарта
  Docker на VPS что-то из внешнего мира не открывается — проверить оба
  этих стека (`docker ps -a`, `docker compose ls` покажет только свои
  проекты — эти два не всплывут, искать `docker-compose.yml` вручную).
- **Топология реверс-прокси на VPS (важно для `BIND_HOST`)**:
  nginx-proxy-manager (`/root/npm`) — на обычной bridge-сети докера, НЕ
  `network_mode: host`. Проксирует `vitazgio.ru` на `172.17.0.1:5000`
  (шлюз docker-моста, не `127.0.0.1` — bridge-контейнер не видит
  `127.0.0.1` хоста, только через `docker0`). Поэтому в `.env` на VPS
  **обязан** стоять `BIND_HOST=172.17.0.1`, не `127.0.0.1` — уже дважды
  чуть не поменяли на `127.0.0.1` по неверному предположению, что раз
  `network_mode: host` у САМОГО сайта, то и прокси на host-сети (нет,
  прокси — отдельный контейнер на bridge). Проверить самому:
  `grep -A2 'set \$server' /root/npm/data/nginx/proxy_host/*.conf` на VPS.

## Зависимости: версии зафиксированы намеренно

В `requirements.txt` у всех пакетов стоит точная версия через `==`
(зафиксировано 2026-09-05 по тому, что реально стояло и работало).
Раньше версий не было — каждая сборка тянула свежее с PyPI, и любой
мажорный релиз (Flask, paramiko, pillow) мог уронить деплой без единой
правки в нашем коде.

Обновлять — **осознанно и по одной**: поднять версию одного пакета,
собрать, открыть сайт глазами, дождаться зелёного CI. Не скопом
(`pip install -U` по всему списку) — иначе при поломке непонятно, кто
именно виноват.

Транзитивные зависимости (werkzeug, jinja2, cryptography и прочее, что
тянется само) не закреплены — их держат в рамках сами пакеты. Если
однажды сборка сломается на пакете, которого нет в нашем списке, —
тогда и дописать его сюда с версией.

## Как проверять (важно)

- Питон: `python3 -c "import ast; ast.parse(open('app.py').read())"`.
- Автотесты: `pip install -r requirements-dev.txt` и `pytest -q` из корня.
  Покрыты вход, манифест/sw.js, дроп (доступ + целость файла), фонотека,
  ETag движка плеера, чаты с нейронкой (на своём фейковом OpenRouter, в
  интернет не ходят). Тесты импортируют КОПИЮ проекта во временной папке,
  поэтому настоящие `data/` и `drop_data/` прогоном не портятся.
  Гоняются в CI дважды: до слияния в main (`claude-automerge.yml`) и перед
  сборкой на VPS (`deploy.yml`) — оба зовут `tests.yml`.
- Ловушка: при переносе вида в blueprint имя эндпоинта получает приставку
  (`cabinet` → `remote.cabinet`), а `url_for` в других файлах об этом не
  знает — падает `BuildError` уже в проде, при вызове. Один раз так
  сломался вход в кабинет (см. `docs/history.md`). Сторожит
  `test_every_url_for_target_exists`.
- Встроенный JS: `scratchpad/jscheck.py` — вытаскивает скрипты со всех
  страниц (включая `/vg-player.js` и `/player/pop` как отдельные пункты) и
  гоняет `node --check`. **Обязательно** после правок шаблонов.
- Ловушка: `\n` внутри питоновской строки `"""..."""` становится настоящим
  переносом и рвёт JS. В шаблонах писать `\\n`. Дважды из-за этого падал дроп.
- Ловушка: локальную переменную-обработчик Escape нельзя звать `esc` — так
  зовётся глобальный html-экранировщик; конфликт даёт TDZ
  «Cannot access esc before initialization» и тихо ломает диалог.
- Живая проверка: Playwright + Chromium
  `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`,
  `NODE_PATH=/opt/node22/lib/node_modules`. Локальный запуск —
  `scratchpad/run.sh` (пароль кабинета `testpass`).

## Как добавлять новую фичу/страницу (правило, не предложение)

После разреза `app.py` на `templates/` + `blueprints/` — так, и никак иначе:

1. **Новый раздел = новый файл** в `blueprints/`, не правка `app.py`.
   Фича **владеет своим состоянием сама**: свои данные, лок, guard'ы,
   переменные окружения — на модульном уровне в её же файле, а общее
   (`login_required`, `template`, хранилище) берётся **прямым импортом**
   из `core/*` и других blueprint'ов. Эталон — `blueprints/debts.py` и
   `blueprints/drop.py`: `create_X_blueprint()` **без единого аргумента**,
   регистрация в `app.py` одной строкой.
   **Не проталкивать зависимости аргументами фабрики** — так было до
   задач 34-40 (у `drop` дошло до 61 аргумента), и именно от этого
   уходили: тогда правка фичи требовала читать и blueprint, и простыню
   регистрации, и `app.py`. Аргументы допустимы только для того, что
   физически общее и ещё не имеет своего дома (`sock`, `NETBIRD_DEVICES`,
   статус пинга) — сейчас таких на весь проект 47, и каждый оставлен с
   объяснением в коммите задачи, а не «так проще».
2. **HTML/JS новой страницы — в `templates/`**, не строкой внутри
   `blueprints/*.py`. Читать через уже существующий `_template()`.
   НЕ Jinja2 — обычный текстовый файл + `.replace()`/`.format()`, если
   нужна подстановка (см. «Ловушки» выше — `\n` и `esc` актуальны и тут).
3. **Перегенерировать опись роутов**: `python3 scripts/gen_routes.py`,
   закоммитить получившийся `docs/routes-inventory.md`. Не редактировать
   его руками — потеряется при следующем запуске, и сторожит
   `tests/test_docs.py`.
4. **Если есть `tests/`** (см. план в задаче на автотесты) — новая
   страница/API получает свой тест сразу, не отдельным заходом потом.
5. **Проверка перед пушем**: `python3 -c "import ast; ast.parse(open('app.py').read())"`
   на все тронутые файлы, `scratchpad/jscheck.py` если трогали JS,
   локально `scratchpad/run.sh` — глазами открыть новую страницу.
6. **Пуш → дождаться зелёного CI** (реальный healthcheck на VPS, не
   только «собралось») — прежде чем сообщать, что фича готова.
7. Следовать уже устоявшимся паттернам сайта, а не изобретать свои:
   свои карточки подтверждений (`uiConfirm`/`uiToast`), не системные
   `confirm()`/`alert()`; цвета через CSS-переменные
   (`color-mix(in srgb, var(--ac) N%, transparent)`), не хардкод; auth —
   `login_required`/специфичный guard, не самодельная проверка сессии.

## Скорость: что уже сделано (не откатывать)

Замеряли — сервер отдаёт страницу за 2-3 мс, то есть бэкенд ни при чём,
переписывать движок незачем. Тормозил объём.

- **gzip на ответах** (`compress_response`, after_request). Уровень 6.
  **Что обходим и почему** (ломать нельзя):
  — `text/event-stream` и генераторы (`is_streamed` без `direct_passthrough`)
    — SSE-чат нейронки, сжатие копило бы буфер и живая печать превратилась
    бы в один рывок в конце;
  — `send_file` с Range: у файлов `is_streamed` ТОЖЕ True, различаем по
    `direct_passthrough` + проверке типа (audio/*, video/*) + `GZIP_FILE_MAX`;
  — не 200 (206 Partial, 304 Not Modified), уже сжатое, мелочь до 1 КБ.
- **Кэш статики**: `/static/*` → сутки (Flask сам ставит `no-cache`, поэтому
  именно перезаписываем, `setdefault` молчал бы).
- **xterm и guacamole — по требованию** (`window.vendorReady`), тянутся
  `openTerminal`/`openRdp` при первом открытии, кэшируются в `done[]`.
  Итог по кабинету: **533 КБ → 49 КБ** по сети.
- Страницу `/claude` намеренно не трогали: там терминал и есть смысл
  страницы, `defer` и так не блокирует отрисовку.

## Дисциплина документации (правила для ВСЕХ будущих чатов)

Этот раздел существует потому, что за две недели `CLAUDE.md` вырос с
20 КБ до 72 КБ, а опись роутов дважды разошлась с кодом.

**Куда что писать:**

| Что | Куда | Предел |
|---|---|---|
| Правила, ловушки, ограничения хозяина, навигация «куда идти» | `CLAUDE.md` | ≤ 25 КБ, сторожит тест |
| Как устроена конкретная фича | `blueprints/<name>.md` рядом с кодом | 30-60 строк |
| «Пробовали X, откатили, вот почему» | `docs/history.md` | только если урок повторяемый |
| План/ТЗ | `docs/<name>-plan.md`, после выполнения — пометка «выполнено» | — |
| Список роутов, размеры, счётчики | **никуда** — генерируется скриптом | — |

**Три правила, которые важнее остальных:**

1. **Не писать в документ то, что можно узнать командой.** Число роутов,
   список файлов, размеры — это `grep`/скрипт, а не строчка в `.md`.
   Записанное число устаревает молча и потом врёт увереннее, чем
   отсутствие числа.

2. **Факт, который важен, — сторожить тестом, а не абзацем.** Если
   что-то «нельзя ломать» — на это пишется тест. Пример, который уже
   спас прод: `test_every_url_for_target_exists` ловит `BuildError` от
   переименования эндпоинта при переносе в blueprint (однажды так
   сломался вход в кабинет). Один такой тест полезнее десяти страниц
   описания.

3. **Перед добавлением абзаца в любой `.md` спросить себя:** переживёт
   ли это следующий рефакторинг? если разойдётся с кодом — кто заметит?
   Если ответ «никто» — не писать.

**Чего не делать:**

- не переписывать `CLAUDE.md` целиком «заодно» — дописывать в нужный
  раздел, не заводя новый под каждую фичу;
- не копировать в `CLAUDE.md` описание своей свежей фичи «чтобы не
  забылось» — для этого есть `blueprints/<name>.md`;
- не вести хронику правок в `CLAUDE.md` — она в `docs/history.md`, и
  только если из неё следует урок на будущее;
- не дублировать один факт в двух файлах: копии расходятся, и потом
  невозможно понять, какая верна.

**Когда фича добавляется (напоминание, подробности в CLAUDE.md):**
новый файл в `blueprints/`, разметка в `templates/`, тест в `tests/`,
описание в `blueprints/<name>.md`, опись роутов — перегенерировать
скриптом, в `app.py` — только регистрация.

## Ограничения, заданные хозяином (соблюдать)

- Себастьян: гости из сети могут болтать, но НЕ управлять домашними
  устройствами. Модель — только та, что уже в памяти видеокарты; новую не
  поднимать (видеопамять занята).
- Страница серверов /servers — публичная: без локальных IP, без публичного
  адреса VPS, без адресов NetBird.
- Пароль корзины дропа хранится хэшем (sha256), не открытым текстом.

## Незакрытое (зависит от хозяина, не от кода)

- `SEBASTIAN_OLLAMA=http://<ubuntu-vm>:11434` на сервере — иначе чат
  Себастьяна не работает.
- `BACKUP_TOKEN` — для внешнего домашнего бэкапера.
- `PHONE_AGENT_TOKEN` — общая строка сайта и телефона, запасной путь на
  случай, если войти в кабинет с телефона не выходит. Обычный путь другой:
  оболочка получает личный токен устройства сама, войдя в кабинет. Не задан —
  общим паролем не пустит, личные токены работают всё равно.
